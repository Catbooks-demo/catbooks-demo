# 캣북스 쇼핑몰을 실제 서점처럼 만들기 — 설계

작성 2026-11-16 · 대상 `Catbooks-demo/catbooks-demo` (`backend/shop-api`, `frontend/shop-web`)

## 1. 왜 하는가

캣북스는 AXcellent 부서 AI들이 일하는 "고객사 쇼핑몰"이다. 지금 쇼핑몰은 비밀번호 없이 시드 구매자 30명 중 한 명을 고르고, 상품 8개를 사는 데모다. 마이페이지·후기·문의 내역 같은 화면은 "준비 중"으로 비어 있다.

목표는 **실제 서점처럼 돌아가는 사이트에 실제 같은 데이터를 넣어 보고, 그 데이터가 AXcellent에서 제대로 처리되는지 확인하는 것**이다. 화면을 예쁘게 채우는 것보다 사람이 가입해서 주문·결제·환불·문의·의견을 남기면 그게 판매 서버에 쌓이고 AXcellent(고객지원·재무·데이터분석·마케팅)로 흘러가는 것이 먼저다.

## 2. 목표 · 하지 않는 것 · 실패로 보는 것

**목표**
- 이메일·비밀번호로 가입·로그인하고, 본인 주문·클레임·문의·의견만 보는 마이페이지
- 교보문고·알라딘 같은 서점의 화면 구성(첫 화면, 목록·검색, 상품 상세, 마이페이지)을 참고한 쇼핑몰. 디자인은 지금 쇼핑몰과 이어지게
- 상품 상세에 책 정보(저자·출판사·ISBN·장르·소개)와 구매 후기
- 구매자 성별(선택), 상품 장르(코드)를 판매 서버에 더해 AXcellent 데이터분석의 고객·시장 분석이 쓸 수 있게
- 지금 AXcellent가 읽는 판매 서버 경로는 모두 그대로 동작

**이번에 하지 않는 것 (나중에)**
- 적립금(포인트) 적립·사용·소멸 — 주문 금액과 재무 장부가 바뀌어서 따로 한다
- 실제 책 데이터 넣기(공개 도서 자료로 수백 권) — 이 작업 다음 단계
- 가상 주문 스크립트(`shop_traffic.py`) 고치기 — 예진이 따로 한다
- 택배사 연동(실제 배송 추적), 소셜 로그인, 이메일 인증·비밀번호 찾기 메일 발송
- 후기를 AXcellent 고객의 소리로 넘기기 — 고객지원(병환)과 따로 정한다

**실패로 보는 것**
- AXcellent 재무·고객지원·데이터분석이 판매 서버를 읽다가 401/403으로 끊기는 것
- 다른 사람의 주문·문의·개인 속성이 보이는 것
- 직업처럼 실제 서점도 받지 않는 개인정보를 받는 것
- 지어낸 ISBN·저자를 실제 정보처럼 넣는 것
- 새 화면만 다른 사이트처럼 보이는 것(디자인 이질감)

## 3. 지금 상태 (조사 결과)

- 판매 서버: FastAPI + SQLite(연결 하나, RLock). 서비스 토큰·연결 키 검증은 `main.py`의 `_caller(allowed)`.
- 구매자용 경로는 토큰이 없다. 요청 본문·쿼리의 `buyer_id`를 믿는다(`/orders`, `/claims`, `/inquiries`, `/ideas`, `/users/{buyer_id}` 등). 새 회원을 만드는 경로는 없다.
- 이미 있는 구매자용 조회: `GET /api/shop/inquiries?buyer_id=`(내 문의), `GET /api/shop/claims?buyer_id=`(내 클레임), `GET /api/shop/ideas?buyer_id=`(내 의견), `GET /api/shop/orders?buyer_id=`.
- 상품: 이름·분류(`book`/`stationery`)·가격·재고 + `isbn13`·`author`·`publisher`(#14, 선택). 시드 8개에는 책 정보가 비어 있다(일부러).
- 구매자: `age_band`(#9, 선택). 화면에서 고르는 칸은 #11.
- 판매 집계 `GET /api/shop/sales-summary`(#12)로 베스트 순위를 낼 수 있다.
- **AXcellent가 판매 서버를 읽는 방식(중요)**
  - 재무 `finance_agent/books.py`: `GET /api/shop/orders`를 **토큰 없이** 페이지로 끝까지 읽는다.
  - 고객지원 `support_agent/shop_client.py`: `GET /api/shop/orders/{id}`는 "토큰이 필요 없다"고 적혀 있다. 정산은 `GET /api/shop/orders`를 토큰 없이 읽는다.
  - 데이터분석 커넥터는 `Authorization: Bearer <data 토큰>`을 붙인다.
  - AXcellent는 가입·주문 생성·내 문의 같은 구매자용 쓰기 경로는 부르지 않는다.
- 화면: React + Vite + Tailwind. 경로 12개(`App.tsx`). 디자인 토큰(`brand`·`ink`·`surface`·`accent`), `btn-primary`·`btn-ghost`·`field` 클래스, 생성 표지 `Cover`, `bits.tsx`의 `PageTitle`·`ErrorNote`·`NotReady`·`Price`.

## 4. 만드는 방식 (고른 것과 이유)

### 4.1 로그인 유지 방식
| 안 | 내용 | 결과 |
|---|---|---|
| **A. DB에 저장한 로그인 토큰을 헤더로** | 로그인하면 무작위 토큰을 주고 DB에는 해시만 둔다. 화면은 `Authorization: Bearer`로 보낸다 | **골랐다** |
| B. HttpOnly 쿠키 | 스크립트가 토큰을 못 읽어 더 안전 | 화면(3000)과 서버(8010) 주소가 달라 쿠키·CORS가 복잡하고, 가상 주문 스크립트도 쿠키를 다뤄야 해서 뺐다 |
| C. 서명 토큰(JWT) | DB 없이 검증 | 로그아웃 즉시 끊을 수 없고, 판매 서버는 어차피 DB가 있어 장점이 없어서 뺐다 |

A를 고른 이유: 지금 판매 서버의 `Authorization: Bearer` 구조와 가장 잘 맞고, 로그아웃하면 바로 끊기고, 스크립트에서 쓰기 쉽다. 브라우저 저장소의 토큰이 XSS에 노출되는 위험은 외부 스크립트를 넣지 않는 것으로 줄인다.

### 4.2 첫 화면 방향
시안 A(큐레이션 중심)·B(정보 촘촘형)·**C(섞은 형태)** 중 C를 골랐다. 배너는 작게, 베스트 순위와 신간을 나란히, 아래에 장르별 줄. 책 수백 권이 들어와도 찾기 쉽고 시연 화면으로도 보기 좋다.

## 5. 정한 것

### 5.1 회원·로그인 (판매 서버)
- 가입: 이메일, 비밀번호, 표시 이름(닉네임). 선택: 연령대(`age_band`), 성별(`gender`). 약관·개인정보 동의(필수), 선택 항목 동의 문구.
- 비밀번호: 표준 라이브러리 `hashlib.scrypt` + 사용자별 솔트. 새 의존성은 추가하지 않는다.
- 로그인 토큰: 무작위 값, DB에는 해시만. 로그아웃하면 지운다.
- 성별: 선택 칸, 코드값만(`female`·`male`·`no_answer`), 비우면 모름. **직업은 받지 않는다**(알라딘·예스24·교보문고 모두 가입 때 받지 않고, 개인정보 최소 수집 원칙).
- 기존 구매자 30명과 251의 기존 주문은 그대로 둔다. 비밀번호 없는 "옛 데모 계정"으로 남고, "구매자 고르기"는 시험용으로만 남긴다.

### 5.2 상품 (판매 서버)
- 장르: 상품에 코드 목록으로 붙인다(자유 글 아님). 목록은 실제 책 데이터를 넣을 때 그 분류에 맞춘다. 이번에는 칸과 검증만 만든다.
- 책 소개(설명 글) 칸을 더한다(선택).
- 목록·검색: 제목·저자·출판사로 찾기, 장르로 거르기, 정렬(인기·신상품·가격).

### 5.3 화면 (`frontend/shop-web`)
- **디자인은 지금 쇼핑몰과 이어지게**: 기존 색·글꼴·버튼·카드·`Cover`·`bits.tsx` 부품을 그대로 쓴다.
- **첫 화면 (C)**: 검색창이 있는 머리글, 분야 메뉴, 작은 이벤트 배너(공지·쿠폰), 베스트 TOP(판매 집계), 새로 나온 책, 장르별 줄.
- **목록·검색**: 장르 메뉴, 검색어, 정렬, 페이지.
- **상품 상세**: 표지 / 책 정보(장르·제목·저자·출판사·출간일·ISBN·판매자) / 별점과 후기 수 / 가격·배송 안내 / 수량·장바구니·바로구매. 아래 탭은 책 소개, 구매 후기, 교환·반품 안내. 맨 아래는 이 분야 베스트.
- **마이페이지**: 위쪽 요약(최근 주문·진행 중 클레임·답변 대기 문의). 왼쪽 메뉴는 이렇게 묶는다.
  - 쇼핑: 주문·배송 조회, 취소·반품·교환, 장바구니
  - 활동: 1:1 문의 내역, 고객의 소리, 내가 쓴 후기
  - 내 정보: 회원정보 수정(연령대·성별), 비밀번호 변경, 로그아웃
- **가입·로그인 화면**: 새로 만든다. 지금 `/login`의 "구매자 고르기"는 시험용 경로로 옮긴다.
- 적립금 자리는 "나중에"로 둔다.

### 5.4 후기
- 그 상품을 결제하고 배송 완료된 구매자만 쓸 수 있고, 주문 품목당 1개.
- 별점 1~5와 글. 다른 사람에게는 이름 대신 "20대"처럼 연령대만 보인다(없으면 "구매자").
- 이번에는 판매 서버에만 쌓는다(AXcellent로 넘기지 않는다).

### 5.5 상품 문의·배송
- 상품 문의 탭은 따로 두지 않는다. 지금 있는 1:1 문의(주문 연결)로 받아 고객지원 AI로 넘긴다.
- 배송 조회는 판매 서버 상태(결제 → 배송 중 → 배송 완료)만 보여 준다.

### 5.6 구매자 경로의 본인 확인 (예진 결정)
- **구매자용 경로는 전부 로그인 토큰을 요구한다**: 주문 만들기·결제·취소, 클레임 신청·내 클레임, 문의 접수·내 문의·피드백, 의견 보내기·내 의견, 내 정보 조회·수정, 장바구니 가격 계산의 쿠폰 확인. 서버는 토큰에서 구매자를 알아내고, 본문·쿼리의 `buyer_id`는 쓰지 않는다(다르면 403).
- **관리자 토큰은 `buyer_id`를 지정해 대신할 수 있다.** 가상 주문 스크립트(예진이 따로 고침)는 관리자 토큰 + `buyer_id`로 넣거나, 시험 회원으로 로그인해서 넣는다.
- "구매자 고르기"(비밀번호 없는 옛 데모 계정 로그인)는 **기본 꺼짐**, 개발·시험 설정에서만 켠다(Claude 판단).
- 회원 전체 목록 `GET /api/shop/users`는 관리자 토큰으로만 읽는다(Claude 판단).

### 5.7 AXcellent와의 경계 (지켜야 하는 것)
- AXcellent가 쓰는 관리자·서비스 경로(`/api/shop/admin/*`, `failed-orders`, `metric-series`, `sales-summary`, `sales-export`, `coupons`, `sellers/*` 등)는 지금 동작을 그대로 둔다. 칸·선택값을 **추가만** 한다. `sales-summary`의 `group_by`에 `gender`·`genre`를 더하는 것도 추가로 본다(Claude 판단).
- **주문 조회(`GET /api/shop/orders`, `GET /api/shop/orders/{id}`)는 당분간 토큰 없이도 전체가 읽힌다**(예진 결정, 그동안 남의 주문이 보일 수 있는 위험은 감수). 재무·고객지원이 토큰 없이 읽고 있어서다.
  - 설정 하나로 이 길을 끌 수 있게 한다(기본 켜짐). 태윤(재무)·병환(고객지원)에게 서비스 토큰을 붙여 달라고 부탁하고, 붙은 뒤 끈다.
  - 구매자 로그인 토큰이 오면 그 구매자 것만 준다. 서비스 토큰·연결 키가 오면 전체를 준다.
  - **알 수 없는 토큰이 오면 401**로 거절한다(전체를 주지 않는다). AXcellent는 토큰을 안 보내거나 맞는 토큰을 보내므로 끊기지 않는다.
- 바뀐 응답 모양은 OpenAPI 고정본(`backend/contracts/openapi/shop-api.json`)을 같이 갱신한다. AXcellent 쪽 사본은 #1115의 매일 점검이 알려 준다.
- 고객지원이 읽는 문의·클레임·아이디어 항목에 `gender`도 `age_band`처럼 싣는다.

### 5.8 장르 (예진 결정)
- **서점식 목록**을 쓴다: 소설, 시·에세이, 경제경영, 자기계발, 인문, 사회·정치, 역사, 과학, IT·컴퓨터, 외국어, 어린이, 만화, 여행·취미, 문구. 코드는 영문 소문자(`novel`, `essay`, `business`, `self_help`, `humanities`, `society`, `history`, `science`, `it`, `language`, `kids`, `comics`, `hobby`, `stationery`). 세부 이름·순서는 만드는 사람이 다듬는다.
- 실제 책을 넣을 때 공개 도서 자료의 도서관 분류(KDC)를 이 목록으로 바꿔 넣는다(다음 단계).
- 상품 하나에 장르 **하나**(Claude 판단, 장르별 집계에서 같은 판매가 두 번 세지지 않게).
- 기존 `category_code`(`book`/`stationery`)는 그대로 둔다. 장르는 그 아래 세분이다.
- 시드 8개에는 장르를 채우지 않는다. 책 데이터를 넣기 전까지 화면의 장르 줄·이 분야 베스트는 비어 있으면 숨긴다(Claude 판단).
